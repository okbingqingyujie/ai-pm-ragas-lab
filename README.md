## 2. 为什么值得 AI PM 学

此前的通用评测学习关注“怎样设计测试与发布判断”。今天只解决一个更具体的问题：知识库助手答错时，产品经理如何用证据判断应改检索、资料，还是生成规则？

Ragas 的官方 README 提供 LLM 与传统指标、测试数据生成和评测集成能力，并列出 `rag_eval` 快速开始模板。本文不把 README 中标为 Coming Soon 的其他快速开始模板视为已经可用，也不复述“无缝集成”这类未经实测的效果承诺。

PM 可交付三个东西：
1. 每道题的标准答案与证据集合，而非只有一个“正确/错误”标签。
2. 检索质量与回答质量分开的验收记录，让工程团队知道该改哪里。
3. 版本比较规则：固定题集、文档版本和评判口径，只改一个变量。

## 3. 三个指标，三个不同问题

| 指标 | 看什么 | 需要什么 | 不应推断什么 |
|---|---|---|---|
| Context Precision | 有用片段是否排在前面 | 问题、按顺序保存的检索片段、参考答案；本文采用有参考答案的口径 | 高分不证明证据齐全 |
| Context Recall | 参考答案中的事实是否被检索证据覆盖 | 参考答案、检索片段 | 高分不证明最后回答正确 |
| Faithfulness | 回答中的事实是否有检索证据支持 | 回答、检索片段 | 高分不证明资料最新，也不证明回答完整 |

官方定义和 API 入口：[Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/)、[Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/)、[Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)。

注意：有参考答案的 Context Precision 与用生成回答判断片段用途的 Context Utilization 不是同一个评判基准。不要混用后比较分数。上述文档同时展示 collections 新接口与 legacy 接口；实现时应固定版本，使用该版本对应文档。

## 4. 45 分钟纸上练习：会议室预约助手

本练习无需安装软件、调用付费模型或上传公司资料。目标是先把评测标注做对，再考虑自动化。

### 4.1 合成资料

这是一个虚构公司的规则，不是任何真实公司的政策：

- D1，现行规则：普通员工单次会议室预约最长为 2 小时。
- D2，现行规则：预约开始前至少 30 分钟，可自行取消。
- D3，现行规则：不足 30 分钟时，须联系行政取消。
- D4，现行规则：会议室提供白板笔。
- D5，历史规则，已失效：普通员工单次预约最长为 4 小时。

主问题 Q1：“普通员工最多能订多久？提前 10 分钟想取消怎么办？”

标准答案包含三个原子事实：F1 最长 2 小时；F2 提前 10 分钟不满足自行取消条件；F3 须联系行政。标准证据为 D1、D2、D3。F2 的判断还需要把问题给出的 10 分钟与 D2 的 30 分钟比较。

### 4.2 两个候选版本

这些都是人为构造的对照，不是系统实际输出。

- 版本 A 检索顺序：D4、D1、D2。回答：“单次最长 2 小时；提前 10 分钟不能自行取消。”
- 版本 B 检索顺序：D1、D2、D3。回答：“单次最长 2 小时；提前 10 分钟不能自行取消；须联系行政；行政保证一分钟内处理。”

先给片段标相关性，再把回答拆成事实并标注证据。不能用分数猜测原因。

### 4.3 人工计算示范

为便于学习，人工固定了上述事实拆分和相关性；实际 Ragas 的模型判分可能因拆分、提示词或评判模型不同而不同。这些数字不是 Ragas 运行结果。

**Context Precision（排名口径）**：对每个相关片段，计算截至其位置的相关片段占比，再对相关片段求平均。

- A 的相关性序列为 [0,1,1]，得分 = (1/2 + 2/3) / 2 ≈ 0.583。
- B 的相关性序列为 [1,1,1]，得分 = (1 + 1 + 1) / 3 = 1。
- 这里不是简单的“相关片段数 / 总片段数”。没有任何相关片段时，要记录该边界条件并核对实现，不能手算除以零。

**Context Recall（参考事实覆盖）**：检索证据能支持的标准事实数 / 标准事实总数。

- A 支持 F1、F2，缺少 F3，得分 2/3。
- B 支持 F1、F2、F3，得分 3/3 = 1。

**Faithfulness（回答事实有据率）**：检索证据支持的回答事实数 / 回答事实总数。

- A 的两个回答事实都有据，得分 2/2 = 1，但漏掉了如何处理取消，仍未完整回答问题。
- B 的前三个事实有据，“保证一分钟内处理”无证据，得分 3/4 = 0.75。

**产品判断**：A 先补检索覆盖，B 先禁止无根据的时效承诺。两者都不能因为某一个分数高就直接通过。若只检索到 D5 并照着回答，Faithfulness 可能很高，但答案仍因使用失效规则而不合格。

### 4.4 再做六个变体

| 用例 | 构造方法 | 预期检查重点 |
|---|---|---|
| Q2 只问最长预约时间 | 仅返回 D1，答案 2 小时 | 简单事实基线 |
| Q3 提前 40 分钟取消 | 返回 D2，答案可自行取消 | 条件数值推理 |
| Q4 提前 10 分钟取消，漏 D3 | 仅返回 D2 | 不虚构联系渠道；标记缺证据 |
| Q5 返回旧规则 D5 | 答案 4 小时 | 现行版本校验，不能只看有据率 |
| Q6 问是否收取取消费 | D1–D4 均无费用规定 | 明确资料不足，不编造免费或收费 |
| Q7 D4 排第一，其余同 B | 只改变检索顺序 | 排名变化与覆盖变化分开记录 |

交付一张记录表：题号、文档版本、参考事实、检索顺序、候选回答、事实证据对应、三个分数、缺失/冲突说明、人工结论。给每条失败标上“资料版本、检索覆盖、检索排序、生成无据、回答不完整”之一，可多选。

## 5. 验收与下一步

以下是本练习的学习标准，不是 Ragas 官方阈值，也不是生产通用上线标准：

- 能复算 A 与 B 的三项结果，并解释 A 的有据率为 1 为什么仍不完整。
- 所有关键事实都有证据编号；任何“保证处理时效”的无据承诺直接判不通过，不被平均分抵消。
- 缺资料、旧版本及无答案题单独统计，不从分母中静默删除；空回答或没有可判定事实的样本记为待人工复核，不自动算满分。
- 修改检索排序时保持生成规则不变；修改提示词时保持同一批检索片段，避免把多个变量效果混在一起。
- 用 Q1–Q4 理解与调整规则，将 Q5–Q7 作为初始盲测；看过后就不再是独立测试集，需增加未见过的新题。

如之后决定写代码，先从 [官方 Quickstart](https://docs.ragas.io/en/latest/getstarted/quickstart) 的 RAG 示例开始，固定依赖、生成模型、评判模型、提示词和数据版本。只使用获准的合成或脱敏数据，记录运行成本和异常，不在 README 中放密钥。此仓库未执行这一步。

## 6. 使用边界

- LLM 评判会受中文表达、事实拆分和模型偏差影响；先人工双人标注少量样本，讨论分歧，再衡量自动评分与人工的一致性。
- 参考答案不完整会让 Recall 看似正常；资料本身错误会让 Faithfulness 误导决策。文档有效期、业务正确性和回答完整性必须独立检查。
- 自动生成的题集适合补充覆盖，不能代替真实用户分布；生成模型与评判模型共享偏差时尤其要保留人工审查。
- Ragas 是评估工具，不会自动修好业务系统，也不会替代权限、隐私和安全控制。实际模型调用可能有费用，开源许可证不代表所有依赖服务免费。
- 本仓库只有学习整理与合成练习，未安装、未部署、尚未实测，没有用户项目成绩或线上收益声明。
